# 改动总结：详情页关键词检索优化

**提交**：`7822ae0` — *优化详情页关键词*  
**日期**：2026-05-09  

## 背景与目标

针对后台「审核详情页」等典型表述，优化组件知识库检索中的关键词补丁与查询扩展规则，使 **详情页头部、状态 Tag、基础信息与记录类区块** 更容易召回对应组件（如 `ZhDetailHeader`、`ZhDetailSubTitle`、`ZhBaseInfo`），并减少对通用表格类组件（如 `ZhTable`、`ZhDiyDataTable`）的误优先。

## 涉及文件

| 路径 | 说明 |
|------|------|
| `packages/server/src/services/component-knowledge/keyword-patches.ts` | 按组件 ID 增补加权关键词 |
| `packages/server/src/services/component-knowledge/query.ts` | 查询意图规则与查询扩展规则 |
| `packages/server/src/services/__tests__/component-knowledge.service.test.ts` | 检索与拆分场景的贯通测试 |

## 核心改动说明

### 1. 关键词补丁（`keyword-patches.ts`）

- **新增 `ZhDetailHeader`**：覆盖「详情页头部 / 详情头部 / 标题栏 / 返回按钮 / 头部操作区 / 状态 Tag」等与详情页顶栏强相关的词。
- **`ZhDetailSubTitle`**：强化状态与 Tag 类语义（如状态 Tag、状态标签、审核/审批状态、流程节点、时间线节点等）。
- **`ZhButton` / `ZhButtonGroup`**：补充「操作按钮」「审核按钮」「操作按钮区」「详情页操作区」「权限按钮」等场景词。
- **`ZhBaseInfo`**：关联「详情页基础信息」「审核/审批记录」「业务历史」「操作日志」「时间线」及卡片类表述，贴近详情页信息区块。
- **`ZhGrid` / `ZhInfoPair`**：布局与字段展示侧补充「左右两栏 / 双栏」「详情字段 / 基础字段」等。
- **`ZhTable`**：少量场景词（待办事项、最近动态、动态列表等），与列表场景对齐。

### 2. 查询逻辑（`query.ts`）

- **意图规则**：在 `component` 类增加「页头」「副标题」；在 `scenario` 类增加「审核记录」「操作日志」「时间线」，便于意图归类与后续扩展命中。
- **查询扩展**：新增多组触发词与扩展词映射，例如：
  - 详情页头部 → 标题栏、返回、操作区、`DetailHeader` 等；
  - 状态 Tag / 审核状态等 → 状态副标题、`DetailSubTitle` 等；
  - 审核/审批记录、操作日志、时间线 → 与基础信息、记录卡片等语义串联；
  - 左右两栏 / 双栏 → 栅格、两列、多列布局；
  - 待办/动态类列表 → 列表、表格等相关扩展；
  - 「信息展示」类触发补充「基础信息区 / 基础信息卡片」，扩展中纳入栅格等。

### 3. 测试（`component-knowledge.service.test.ts`）

- **单查询**：验证「后台审核详情页头部：标题、状态 Tag、返回按钮和操作按钮区」能召回 `ZhDetailHeader`、`ZhDetailSubTitle`。
- **需求拆分 + 检索**：对完整后台审核详情页描述走 `decomposeRequirement` + `retrieveKnowledgeForDecomposition`，断言 `pageType` 为 `admin-detail`，且结果中包含 `ZhDetailHeader`、`ZhDetailSubTitle`、`ZhBaseInfo`，且前若干条不应被表格组件独占前排。

## 验证方式

在 `packages/server` 下运行组件知识相关测试（例如 Vitest/Jest 项目中针对 `component-knowledge.service.test.ts` 的用例）即可回归上述行为。
